## 3. 사용자와 확정한 결정

- **계정**: 이메일 없음. 슈퍼관리자(사용자)가 아이디 + 임시 비밀번호 발급, 최초 로그인 시 변경 강제. 역할 없음, 같은 기관 계정끼리 서로 발급·초기화·비활성화 가능.
- **구조**: 기관 → 행사 → 부스. 행사 안에 **운영 단체(partner)**가 부스를 묶고 실적 링크(`/p/:token`)를 가짐. 운영 단체는 다른 기관 계정과 **연결** 가능(연결 기관은 그 부스만 '관리' 권한, 행사 단위 접근 없음).
- **부스 관리**: 로그인 없는 부스 링크 `/b/:token`(운영 시작/마감, 설정, 명단, 엑셀, 초기화).
- **방문객 주소**: `/nareum`, `/gmyouth` 같은 기관 slug 경로. 기존 QR `/reserve/:id`는 새 주소로 자동 이동.
- **정원**: 노쇼·대기자는 정원에서 제외(노쇼 처리 시 자리 다시 열림). 대기→확정은 현장 수동.
- **이관**: "2026년 광명시 청소년의 달 기념행사 오월의 난장" → 광명시청소년재단(`gmyouth`), "기본 행사(미분류)"와 그 부스·신청은 버림, 나머지 → 나름청소년활동센터(`nareum`).
- **감사 로그 열람 화면** 필요(이메일 발송·대기자 자동 승급·알림은 불필요).
- **2단계**: 기능 + 디자인 개편을 한 번에. TypeScript + TanStack Query + Tailwind 4.
- **디자인**: "현장 입장권"(B안). 잉크 `#16181d` + 입장권 종이 `#f3efe4` + 노랑 `#ffcc1a`, 상태는 도장, 절취선, 둥글기 4/6/8px, 프리텐다드 하나. **사용자는 "AI slop" 디자인(큰 둥근 카드, 이모지, 기본 Tailwind 파랑, 장식 그림자, 색만 다른 통계 카드)을 싫어함** — 규칙이 `tests/design-rules.test.ts`로 고정돼 있음.
- **로고**: 기관 로고 + 행사별 공동 로고 업로드(PNG/JPG/WebP ≤1MB), 행사 안내 문구.

## 5. 사용자 결정 대기 / 열린 문제

1. **운영 API 주소**: `.env.production`에 기존 `https://child-api.team-cluster.kr`를 넣음 — 사용자 확인 필요.
2. **방문객 IP당 제한**(백엔드): 신청 1분 30회, 조회·취소 15분 20회, 잘못된 링크 15분 30회. 행사장 와이파이/통신사 공유 IP에서 오픈 직후 걸릴 위험 → 늘릴지, IP+부스 단위로 바꿀지 결정 필요. 미결정이면 현재 값 유지하고 진행하기로 함.
3. **배포 서버**: 새 `.htaccess`는 Apache 2.4 이상 필요. 깊은 주소의 index.html이 no-cache로 나가는지 실제 서버에서 확인 필요. 백엔드 `TRUSTED_PROXY_HOPS`는 전환 후 `whoami-ip`로 확인(README 절차).
4. **부스 링크 노출 정책**: 연결 기관·실적 링크 사용자도 부스 관리 링크(QR)를 볼 수 있음 → 연결 해제해도 재발급 전까지 유효. 사용자가 원하면 소유 기관만 보이게 변경 가능.
5. **휴대폰 카메라 QR 인식**은 미확인(프로그램 디코딩만 확인).
6. 프론트 stash 하나(package-lock 변경) 남아 있을 수 있음 — 권한상 삭제 못 함, 무해.

## 6. 다음에 할 일: 2-C 관리자 화면

범위는 2단계 스펙 **4.3절**(관리자 화면 표)과 **9절** 2-C 행.

1. `superpowers:writing-plans` 스킬로 **2-C 구현 계획** 작성 → `NR_ChildDay2026/docs/superpowers/plans/YYYY-MM-DD-stage2c-admin.md`. 포함할 것:
   - 인증: `AuthProvider`(`GET /api/admin/auth/me`, csrf 보관 `setCsrf`), `RequireAuth`(`next` 보존, 외부 주소 차단, 변경 의무 → `/manage/password`), `nr:unauthorized` 이벤트 처리(클라이언트에 이미 있음), 로그인·비밀번호 변경 화면. walnutphoto `admin/src/auth/` 참고.
   - 관리자 레이아웃(잉크 사이드바 + `paper-2` 본문, 휴대폰에서 접히는 메뉴).
   - 대시보드(`GET /orgs/<org>/overview`: owned + linked).
   - 행사 상세 탭: 부스(목록·추가·엑셀 일괄 등록 `POST /events/<id>/booths/bulk` 422 `fields.rows` → 엑셀 행 번호 = 인덱스+2·일괄 운영 `POST /booths/batch-status`), 운영 단체(생성·연결 기관 `link-targets`·실적 링크 QR·재발급·삭제·배정), 실적(`StatsPanel` + `POST /stats`, `/export`), 링크·QR 모음(zip — `jszip` 추가, 링크 엑셀), 설정(이름·로고 업로드 `PUT /events/<id>/logo`·안내 문구·이름 재입력 삭제).
   - 부스 상세: `BoothConsole` + 관리자용 `BoothSource`(`/api/admin/booths/<id>`…, 명단 `GET /booths/<id>/reservations`, 통계 `POST /stats`), 소유 권한일 때 `extraOwnActions`(행사 이동·운영 단체 배정·재발급·삭제).
   - 계정(내 계정, 기관 계정 발급·초기화·비활성화 — 임시 비밀번호 1회 표시+복사), 활동 기록(`GET /orgs/<org>/audit`, 더 보기 `next_before`, 종류 필터), 기관 설정(로고), 슈퍼관리자(기관 CRUD, 기관별 계정, 전체 활동 기록, 백업 다운로드, whoami-ip).
   - 2-B 최종 리뷰에서 "2-C 초반에 고칠 것"으로 분류된 항목: `Tabs`의 `aria-controls`/`tabpanel`/Home·End, `DataTable` caption·키보드 스크롤, `BoothLinkPage`·`PartnerPage`에 `<main>`/h1.
   - 마지막 태스크: 실제 동작·화면 확인(2-B Task 9 방식, 시드 + Playwright, 캡처는 `docs/verification/2c/`).
2. 계획을 사용자에게 보여주고 승인받은 뒤 **서브에이전트 방식**(`superpowers:subagent-driven-development`)으로 실행 — 사용자가 이 방식을 선택해 왔음.
3. 2-C 완료 후: 두 저장소 `update` → 운영 전환(백엔드 README 절차: 기존 컨테이너 정지 → DB 복사 → 이관 스크립트 → 새 컨테이너 `--restart unless-stopped` → `flask create-superadmin` → 계정 발급 → 기존 관리자 QR을 부스 링크 QR로 교체 안내), 이후 `main` 머지는 사용자 확인 후.

## 7. 작업 방식 메모 (이전 세션에서 굳어진 것)

- 사용자와는 한국어, 결정이 필요하면 선택지와 추천을 제시하고 한 번에 하나씩 질문.
- 각 계획은 SDD로: 태스크마다 구현 서브에이전트(sonnet) → 검토 서브에이전트(sonnet, 보안·핵심은 opus) → 수정 라운드 → 마지막에 opus 전체 검토 → 수정 1회 → 재검토. 진행 기록(ledger)은 각 저장소 `.superpowers/sdd/<plan>/progress.md`(git 무시), 끝나면 삭제.
- 서브에이전트 커밋 trailer는 작성 모델 이름(Sonnet) 그대로 두기로 함. 사용자 직접 요청 커밋은 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- 커밋 메시지: `[feat]/[fix]/[test]/[docs]/[chore] 한국어 요약`.
- 되돌릴 수 없는 삭제(브랜치·stash 등)는 권한 확인에서 막힐 수 있음 → 사용자에게 명령을 안내.
- 로컬 환경: Windows, Git Bash/PowerShell, Python 3.14(Docker 대상은 3.11), Node 24. Docker 없음. 로컬 실행 예: 백엔드 `SESSION_COOKIE_SECURE=0 CORS_ORIGINS=http://localhost:5173 TRUSTED_PROXY_HOPS=0 DATA_DIR=<임시> flask --app wsgi.py run -p 5005`, 프론트 `VITE_API_TARGET=http://localhost:5005 npm run dev`.
- 운영 DB(`NR_ChildDay2026-BE/db/reservations.db`)는 로컬 사본이며 **절대 수정하지 않음**.

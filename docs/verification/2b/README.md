# 2-B 동작·화면 확인 기록

실제 백엔드(Flask, 시드 데이터)와 프론트 개발 서버(Vite proxy)를 붙여 Chromium(Playwright)으로 확인했어요. 화면은 390x844(`m-`)와 1440x900(`d-`) 두 크기로 캡처했어요.
시드: `python scripts/seed_demo.py --out <DATA_DIR>/app.db` (백엔드 저장소). 구동 환경: `SESSION_COOKIE_SECURE=0 CORS_ORIGINS=http://localhost:5173 TRUSTED_PROXY_HOPS=0`, 프론트 `VITE_API_TARGET=http://localhost:5005 npm run dev`.

| 8 | 폐기된 토큰 `/b/없는토큰`, `/p/없는토큰` | 통과 | "이 링크는 더 이상 쓸 수 없어요." `m-14`. 없는 slug 는 `m-15` |

## 화면 규칙 검토

| 항목 | 결과 | 비고 |
|------|------|------|
| 토큰 외 색 없음 | 통과 (수정 1건) | 체크박스가 브라우저 기본 파랑이었음(D3), 수정 후 accent 가 `ink` 로 계산됨 |
| 둥글기 3단계 | 통과 | 캡처상 4/6/8px 만 사용, 절취선 홈만 원형 |
| 도장·절취선이 의미 있는 곳에만 | 통과 | 도장은 마감·운영 중·상태, 절취선은 입장권·부스 줄에만 |
| 긴 이름 줄바꿈, 가로 스크롤 없음(390) | 통과 | 40자 넘는 행사 이름·부스 이름: 목록, 신청, 입장권, 부스 링크 콘솔 모두 `scrollWidth <= clientWidth` (`m-02`, `m-12`, `m-13`, `m-29`) |
| 키보드 포커스 표시 | 통과 (수정 1건) | 종이 면에서 `ticket`(노랑) 외곽선이 나왔음(D1). 수정 뒤 `rgb(22,24,29)` 2px (`m-16-focus-ring-fixed`) |
| 글자 대비 | 통과(육안) | 도구로 대비율을 재지 않고 캡처를 눈으로 확인 |

## 발견한 결함과 수정

| ID | 결함 | 수정 | 커밋 |
|----|------|------|------|
| D1 | 잉크 화면 안의 종이 면(입장권 본문·대화상자·확인 폼)에서 포커스 외곽선이 노랑으로 상속돼 종이 위 대비가 낮음 | `.on-paper :focus-visible { outline-color: ink }` 추가, 해당 면에 `on-paper` 적용 (테스트: 컴포넌트·design-rules) | `[fix] 잉크 화면 안 종이 면의 포커스 외곽선을 ink 로 복원` |
| D2 | 정원이 찬 대기 접수 선착순 부스의 신청 화면에 대기 안내가 없음(타임별 부스는 슬롯에 "대기" 표시가 있음) | "정원이 다 찼어요. 지금 신청하면 대기자로 접수돼요." 안내 추가 (테스트 2건) | `[fix] 정원이 찬 대기 접수 선착순 부스에 대기자 접수 안내 추가` |
| D3 | 설정의 대기 접수·실적 부스 선택 체크박스가 브라우저 기본 파랑 | `accent-ink`, design-rules 에 "모든 체크박스는 accent-ink" 검사 추가 | `[fix] 체크박스 브라우저 기본 파랑 제거(accent-ink)` |

## 전체 확인

프론트 `npm test`(159 통과), `npm run typecheck`, `npm run build`(청크 검사 통과), `npm run lint` 모두 통과. 백엔드 `python -m pytest -q` 194 통과.

## 참고

- 캡처 파일 번호가 `-fixed` 로 끝나는 것은 수정 뒤 다시 캡처한 것이에요(`m-09`, `m-16` 은 수정 전 화면이 남아 있음).
- 확인 도구(Playwright 스크립트 등)는 저장소 밖(작업 폴더 `run/pw`)에 있어요.
